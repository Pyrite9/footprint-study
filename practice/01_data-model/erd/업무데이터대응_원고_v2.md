# 단위 업무와 데이터 대응

> 기준 문서: 업무 기능도 및 업무 기술서 v1.3, 데이터 모델 v4, 데모 코드(2026.11.12)
> 대상 업무: 단위 업무 29개, 기술서 밖 추가 업무 6개
> 대상 엔티티: 회원부터 알림까지 12개
> 구성: 업무 목록, 업무별 데이터 처리, 엔티티별 사용 업무, 상태, v1 대비 변경

## 가. 개요

1) 업무 기능도 및 업무 기술서 v1.3의 단위 업무 29개와, 기술서 밖에서 더한 업무 6개가 데이터 모델의 엔티티 12개를 어떻게 다루는지 정리함
2) 단위 업무마다 사용자와 다루는 데이터를 적고, 업무와 엔티티의 생성, 조회, 수정, 삭제를 대응표로 나타냄
3) 아래 네 가지 조회는 거의 모든 업무에 공통으로 들어가므로 대응표에 적지 않음
   - 로그인한 회원 확인: 회원 조회
   - 접근 범위 확인: 그 조의 조원인지, 과제를 만든 교수인지 보려고 조 참여와 과제를 조회
   - 과제 단계 확인: 조 운영과 과정 기록의 쓰기 요청 전에 과제를 조회
   - 이름 표시: 화면에 조원 이름을 보이려고 회원을 조회
4) 과정 기록은 지우지 않으므로, 화면에서 "삭제"나 "취소"인 업무도 데이터에서는 시각 속성을 채우는 수정임. 실제로 행을 지우는 것은 평가 임시 저장뿐임
5) 업무 규칙을 데이터베이스와 서버 중 어디서 검사하는지는 데이터 모델 보고서의 [표 26] 업무 규칙과 검사 위치를 따름

※ 용어: 엔티티(관리할 대상), 속성(엔티티가 가진 값), 생성(새 행을 저장함), 조회(저장된 행을 읽음), 수정(저장된 행의 값을 바꿈), 삭제(행을 지움), 기록 단계(과정 기록을 남기는 과제 단계), 평가 단계(과정 기록을 바꾸지 않고 동료평가를 받는 과제 단계), CSV(Comma-Separated Values, 쉼표로 값을 나눈 표 파일)

[표 1] 엔티티와 테이블 이름

| 엔티티 | 테이블 | 뜻 |
|---|---|---|
| 회원 | member | 서비스에 로그인하는 교수와 학생 |
| 과제 | assignment | 교수가 만든 조별과제와 진행 단계 |
| 조 | team | 과제 아래에서 함께 작업하는 학생 묶음 |
| 조 참여 | team_member | 회원 한 명이 조 하나에 속한 것. 지금 역할과 조장 여부 |
| 역할 이력 | role_history | 역할을 바꾸기 전의 역할명과 바꾼 시각 |
| 조장 교체 이력 | leader_history | 이전 조장, 새 조장, 바꾼 시각 |
| 산출물 | deliverable | 조원이 올린 파일 하나와 올릴 때의 역할명 |
| 기여 항목 | contribution | 파일이 남지 않는 일의 기록과 완료 보고 |
| 완료확인 | confirmation | 다른 조원의 산출물이나 기여 항목을 확인한 기록 |
| 평가 | evaluation | 제출한 동료평가. 평가자와 대상마다 한 행 |
| 평가 임시 저장 | evaluation_draft | 제출 전에 저장한 동료평가 |
| 알림 | notification | 회원이 화면에서 받는 알림 |

## 마. 상태와 바뀌는 속성

1) 상태를 따로 저장하지 않고, 시각 속성이 비었는지로 판정함
2) 아래 표에 없는 속성은 행을 만든 뒤 바뀌지 않음

[표 13] 상태 판정

| 엔티티 | 상태 | 판정 조건 |
|---|---|---|
| 과제 | 기록 단계, 평가 단계 | 과제 단계 속성. 평가 단계일 때만 평가 시작 시각이 있음 |
| 산출물 | 올림, 삭제됨 | 삭제 시각이 비었으면 올림 |
| 기여 항목 | 보고 전 | 보고 시각과 취소 시각이 모두 비었음 |
| 기여 항목 | 보고됨, 취소됨 | 보고 시각이 있으면 보고됨, 취소 시각이 있으면 취소됨 |
| 완료확인 | 유효, 취소됨 | 취소 시각이 비었으면 유효 |
| 동료평가 | 미제출, 제출 | 평가자의 평가 행이 있으면 제출. 임시 저장만 있으면 미제출 |
| 알림 | 읽지 않음, 읽음 | 읽은 시각이 비었으면 읽지 않음 |
