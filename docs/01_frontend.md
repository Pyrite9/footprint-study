## 6주차 (10.26 ~ 11.01) — 골격 실행, 첫 목록 화면

- 데이터 모양이 API 명세를 따릅니다.

- 화면 주소의 번호를 쓰는 useEffect는 두 번째 인자에 그 번호를 넣습니다. 1단계의 `[]`와 다릅니다. 번호가 바뀌면 다시 불러와야 하기 때문입니다.

## 7주차 (11.02 ~ 11.08) — 입력 양식과 오류 처리

**왜 배우는가**
12.11 시연에서 사람이 직접 입력하는 단계는 모두 양식입니다. 예를 들어 과제 생성, 역할 배정, 동료평가 입력이 있습니다. 양식에서 요청을 보내고, 실패하면 이유를 화면에 보여 주어야 합니다. 서버는 실패하면 `code`가 들어 있는 같은 모양의 응답을 돌려줍니다. 골격의 공통 함수는 실패하면 이 `code`를 담아서 오류를 던집니다. 화면은 이 `code`를 보고 문구를 고릅니다.

### 공통

- [ ] 양식을 제출하면 공통 함수로 요청을 보냅니다. 성공하면 목록을 다시 불러오거나 다른 화면으로 이동합니다.
  - 찾아볼 것: `skeleton/README.md`의 `client.js` POST 예시, `react router useNavigate`
- [ ] 실패한 오류의 `code`에 따라 다른 문구를 보여 줍니다. `code` 목록은 `docs/decisions.md`에 있습니다.
- [ ] 보내는 중에는 버튼을 누를 수 없게 합니다. 두 번 눌러서 두 번 저장되는 것을 막습니다.
  - 찾아볼 것: `react button disabled while submitting`

### 담당 화면

- 김효민
  - [ ] 과제 생성 양식을 만듭니다. 과제명, 시작일, 종료일을 받습니다.
  - [ ] 과제 목록에서 과제를 누르면 과제 상세 화면으로 이동합니다. 과제 정보와 조 목록을 보여 줍니다.
- 윤장현
  - [ ] 역할 배정 화면을 만듭니다. 조원 목록 옆에 역할명 입력칸과 저장 버튼을 둡니다. 저장하면 목록에 바뀐 역할명이 보입니다. 가짜 API에서 저장되는지 확인합니다.
- 양원야
  - [ ] 동료평가 입력 화면을 만듭니다. 평가할 조원을 고르고, 6개 항목마다 1 ~ 5점 중 하나를 고릅니다. 서술 의견은 선택입니다. 평가할 조원 목록은 조원 목록 API로 가져옵니다.
  - [ ] 항목마다 1점, 3점, 5점의 행동 기준 문장을 보여 줍니다. 항목과 문장은 골격의 `src/constants/`에 들어 있습니다. 문장을 직접 바꾸지 않습니다.
  - [ ] 6개 점수는 객체 하나의 state로 관리합니다.
    - 찾아볼 것: `react.dev updating objects in state`, `react radio button group`
  - [ ] 6개 항목을 모두 고르기 전에는 저장 버튼을 누를 수 없게 합니다. "모두 골랐는지"는 state로 두지 않고 점수 객체에서 계산합니다. `docs/decisions.md`의 "다른 값으로 계산할 수 있는 값은 state로 두지 않음" 규칙입니다.
    - 찾아볼 것: `javascript Object.values every`

**제출물:** 담당 양식과 실행 화면 캡처. 실패 화면 캡처 1장. 실패 화면은 가짜 API를 끈 상태에서 양식을 제출해서 만듭니다. 가짜 API는 빈 값도 저장하기 때문입니다. `code`별 문구는 8주차에 실제 서버에서 확인합니다. 마감은 11.08(일) 밤입니다.

**밀리면 뒤로 보내는 순서:** 버튼 중복 클릭 막기 → `code`별 문구(하나의 오류 문구로 먼저 표시)

※ 용어 — 양식(form): 사용자가 값을 입력하고 제출하는 화면 요소 · useNavigate: 코드에서 다른 화면으로 이동시키는 기능 · 행동 기준 문장: 동료평가에서 점수마다 "이런 행동을 했으면 이 점수"를 적은 문장 · radio 버튼: 여러 개 중 하나만 고르는 입력칸

## 8주차 (11.09 ~ 11.15) — 마무리, 실제 서버와 연결

**왜 배우는가**
이번 주에 담당 화면이 모두 갖춰집니다. 그리고 처음으로 가짜 API가 아니라 함께 맞출 사람의 실제 서버에 연결합니다. 가짜 API는 입력을 검사하지 않고 파일도 저장하지 않습니다. 실제 서버에 연결해 보아야 오류 처리와 업로드가 정말 동작하는지 알 수 있습니다.

### 담당 화면

- 김효민
  - [ ] 과제 상세 화면에 "조 추가" 양식을 만듭니다. 조 이름과 조장을 고릅니다. 조장은 학생 목록 API로 가져온 학생 중에서 고릅니다.
    - 찾아볼 것: `react select option controlled`
- 윤장현
  - [ ] 조 합류 화면을 만듭니다. 초대 코드를 입력하면 합류 요청을 보냅니다. 없는 코드면 "초대 코드를 찾을 수 없습니다"를 보여 줍니다. 가짜 API에서도 이 오류가 나오게 골격이 준비되어 있습니다.
- 양원야
  - [ ] 산출물 업로드 양식을 만듭니다. 파일 하나와 역할을 골라서 보냅니다. 파일은 JSON이 아니라 FormData로 보냅니다. 연결하는 날 전까지 먼저 만듭니다.
    - 찾아볼 것: `MDN FormData`, `react input type file`, `skeleton/README.md`의 `client.js` FormData 예시

### 실제 서버와 연결

연결 날짜는 11.09(월) 확인에서 정합니다. 11.13(금)까지 대면으로 합니다. 팀 조장이 함께 있습니다. 백엔드 담당의 컴퓨터 한 대에서 상대의 서버와 본인의 화면을 함께 실행합니다.
