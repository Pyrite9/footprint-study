발자국 화면 지도

화면마다 어떤 컴포넌트를 만들어야 하는지 그렸습니다. 오른쪽 데모 화면의 색 테두리 하나가 컴포넌트 하나입니다. 테두리나 왼쪽 박스를 누르면 그 컴포넌트가 화면에서 하는 일이 나옵니다. 내 이름을 누르면 내가 만들 것만 남습니다.

담당

주차 로드맵

주마다 어느 컴포넌트까지 만드는지 정한 로드맵입니다. 11월 30일에 1주차를 시작하고 1월 31일에 9주차가 끝납니다. 표의 주를 누르면 그 주에 할 일이 아래에 자세히 나옵니다. 밑줄이 있는 주가 이번 주입니다.

이미 있는 것

팀 조장이 데모에서 새 저장소로 옮겨 둡니다. 조원은 만들지 않고 가져다 씁니다.

공통 부품 7개TopBar, Icon, PageLoading, PageError, ConfirmBox, DetailPanel, LogoMark
주소 연결App.jsx에 모든 주소가 연결되어 있습니다. 화면은 제목 한 줄짜리 껍데기입니다.
모양index.css를 그대로 씁니다. 데모와 같은 className을 쓰면 같은 모양이 나옵니다.
저장소와 규약저장소는 github.com/Pyrite9/footprint입니다. 규칙은 저장소의 docs/conventions.md에 있습니다.
로그인과 틀로그인 화면, 왼쪽 레일과 메뉴(AppLayout)가 있습니다. 서버의 로그인과 Entity, Repository도 있습니다.
서버 부르기api/client.js, format.js, constants, 가짜 API가 있습니다.

진행 방법

화면 하나를 아래 과정으로 만듭니다. 어느 주에 어느 화면을 만드는지는 위의 주차 로드맵에 있습니다.

화면 하나를 만드는 과정

  1. 1
    내 화면을 찾습니다.아래에서 내 이름을 누릅니다. 박스를 누르면 화면에서 맡은 자리와 하는 일이 나옵니다.
  2. 2
    껍데기 page를 엽니다.주소는 이미 연결되어 있습니다. 주소를 열면 제목 한 줄이 보입니다.
  3. 3
    가짜 데이터로 컴포넌트를 그립니다.page 안에 데이터를 상수로 적습니다. 컴포넌트를 만들고 props로 넘깁니다. props 이름은 데모와 같게 합니다.
  4. 4
    상수를 API 호출로 바꿉니다.가짜 API를 켜고 page에서 데이터를 불러옵니다. 컴포넌트는 고치지 않습니다.
  5. 5
    불러오는 중과 오류를 처리합니다.공통 부품 PageLoading과 PageError를 씁니다.
  6. 6
    쓰기 동작을 넣습니다.등록, 삭제 같은 동작입니다. 읽기 화면은 이 순서를 건너뜁니다.
  7. 7
    데모 화면과 비교하고 PR을 올립니다.오른쪽 데모 화면과 같으면 끝입니다. 저장소 맨 위에서 node harness/check.mjs를 실행하고, 통과하면 PR을 올립니다. PR은 화면 하나씩 올립니다.

규칙

  • 내 파일만 고칩니다.App.jsx, index.css, 공통 부품은 팀 조장만 고칩니다. 고칠 일이 생기면 단체방에 말합니다.
  • 빈자리는 비워 둡니다.빈자리 표시가 있는 박스는 지금 만들지 않습니다. 그 컴포넌트의 담당이 만든 뒤에 끼웁니다.
  • 데이터와 state는 page가 갖습니다.컴포넌트는 props만 받아서 그립니다. 컴포넌트 안에서 API를 부르지 않습니다.
  • 데모 원본을 보면서 직접 입력합니다.복사해서 붙여 넣지 않습니다. 주석은 내 말로 씁니다.
  • 로드맵의 주에 맞춰 만듭니다.그 주에 정해진 컴포넌트까지 만드는 것이 목표입니다. 앞 주의 것을 건너뛰지 않습니다.
  • 서버 담당은 API 하나씩 만듭니다.Entity와 Repository는 이미 있습니다. DTO, Service, Controller 순서로 만들고 Postman으로 확인합니다.
