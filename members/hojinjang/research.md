# 구현 조사서 - 장호진

- 맡은 것: 조, 합류, 역할 (백엔드)
- 범위: [역할 카드](../../mission/mission2/roles.md#장호진)
- 적는 방법과 예시: [2차 미션 안내](../../mission/mission2/README.md)

찾지 못한 칸에는 "모르겠음"이라고 적고, 시간이 부족하면 첫 번째 부분만 채워서 내도 됩니다.
3번의 "지금 만들 수 있는지"에는 "있음", "없음", "모르겠음" 중 하나를 적습니다.

## 초대 코드 발급, 조원 목록, 역할 지정

### 1. 흐름

1. 조장이 조 홈에서 "초대 코드 발급" 버튼을 누른다
2. 화면에 초대 코드가 보이고, 조장이 그 코드를 조원들에게 알려 준다
3. 조원 목록 화면에서 조원 이름, 조장 여부, 지금 역할을 본다
4. 조장이 조원 한 명을 골라 역할 이름을 입력하고 "저장" 버튼을 누른다
5. 조원 목록에 바뀐 역할이 보인다

### 2. 데이터

| 테이블 | 저장하는 값 | 읽는 값 |
|---|---|---|
| `team` | `invite_code` (발급, 다시 발급하면 새 코드로 바뀜) | `id`, `name`, `assignment_id` |
| `team_member` | `role_name`, `role_assigned_at` (역할 지정 시각) | `id`, `team_id`, `member_id`, `leader`, `role_name` |
| `role_history` | 역할이 바뀔 때 이전 역할 기록 | `team_member_id` |
| `member` | | `id`, `name` (조원 이름) |

### 3. 주고받는 것

| API | 받는 값 | 돌려주는 값 | 지금 만들 수 있는지 |
|---|---|---|---|
| `POST /teams/{teamId}/invite-code` | 조 번호 | 새 초대 코드 | 없음 |
| `GET /teams/{teamId}/members` | 조 번호 | 조원 목록 (조 참여 번호, 이름, 조장 여부, 역할) | 있음 |
| `PATCH /teams/{teamId}/members/{teamMemberId}/role` | 조 참여 번호, 역할 이름 | 바뀐 조원 정보 | 모르겠음 |

### 4. 막아야 하는 경우

| 어떤 경우 | 어떻게 되어야 하는지 |
|---|---|
| 조장이 아닌 조원이 초대 코드를 발급하려 할 때 | 거절한다 |
| 다른 조의 조원 목록을 보려 할 때 | 거절한다 (다른 조의 기록은 볼 수 없음) |
| 조장이 아닌 조원이 역할을 지정하려 할 때 | 거절한다 |
| 다른 조의 조원에게 역할을 지정하려 할 때 | 그 조의 조원이 아니라고 알려 준다 |
| 역할 이름이 비어 있을 때  | 입력하라는 창이라던지 알림을 보낸다? |

## 합류와 조 정보

### 1. 흐름

1. 학생이 합류 화면에서 조장에게 받은 초대 코드를 입력한다
2. "합류" 버튼을 누른다
->  합류버튼을 누르면 조 홈으로 들어가면 산출물이 보이는데 그것 보단 조 이름, 조원이랑 역할명 등이 보이는게 좋아보여 의견제시 

### 2. 데이터

| 테이블 | 저장하는 값 | 읽는 값 |
|---|---|---|
| `team` | | `id`, `name`, `assignment_id`, `invite_code` (입력한 코드로 조 찾기) |
| `team_member` | `team_id`, `assignment_id`, `member_id`, `leader` (false) | 같은 과제에 이미 참여했는지 |
| `assignment` | | 과제이름 |

### 3. 주고받는 것

| API | 받는 값 | 돌려주는 값 | 지금 만들 수 있는지 |
|---|---|---|---|
| `POST /teams/join` | 초대 코드 | 합류한 조 번호와 조 참여 번호 | 없음 |
| `GET /teams/{teamId}` | 조 번호 | 조 이름, 과제 이름, 내 조 참여 정보 | 있음 |

### 4. 막아야 하는 경우

| 어떤 경우 | 어떻게 되어야 하는지 |
|---|---|
| 없는 초대 코드를 입력했을 때 | 코드가 맞지 않는다고 알려 준다 |
| 같은 과제의 다른 조에 이미 참여한 학생이 합류하려 할 때 | 이미 이 과제의 조에 있다고 알려 준다 `assignment_id`, `member_id`로 uk 이므로 check 막는다 |
| 이미 들어간 조에 다시 합류하려 할 때 | 이미 참여한 조라고 알려 준다 |
| 교수가 합류하려 할 때 | 거절한다 |
| 로그인하지 않은 사람이 요청할 때 | 거절한다 |
| 자기 조가 아닌 조의 정보를 보려 할 때 | 거절한다 |

## 5. 배워야 하는 것

3번에서 "없음"이나 "모르겠음"이라고 적은 것을 골라서 적습니다.

| 3번에서 고른 것 | 배워야 하는 것 | 찾아본 자료 |
|---|---|---|
| `POST /teams/{teamId}/invite-code` | 겹치지 않는 초대 코드를 만드는 방법, 겹쳤을 때 다시 만드는 방법 | https://sonoopy.tistory.com/51 |
| `POST /teams/{teamId}/invite-code`, `PATCH .../role` | 로그인한 사람이 누구인지 서버가 알고, 그 사람이 조장인지 검사하는 방법 | 구글에 물어봤음 |
| `PATCH .../role` | 역할 바꾸기와 `role_history` 저장을 한 번에 처리하는 방법(트랜잭션) | https://dhbang.tistory.com/123 |
| `POST /teams/join` | UNIQUE 위반 오류를 받아서 "이미 참여함" 메시지로 바꾸는 방법 | 모르겠음 |
