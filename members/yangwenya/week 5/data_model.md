1. 내 엔티티: 회원(member)

1-1. 업무 규칙

1. 교수와 학생은 모두 회원이다.
2. 회원은 이메일 주소를 로그인 아이디로 사용한다.
3. 같은 이메일 주소로 회원이 두 번 만들어질 수 없다.
4. 화면에 회원의 이름이 표시된다.
5. 회원 유형은 교수(PROFESSOR)와 학생(STUDENT) 두 가지이다.
6. 학교 구글 계정으로 가입한 회원은 비밀번호가 없을 수 있다.
7. 비밀번호를 저장하는 경우 해시(hash) 값으로 저장한다.
8. 교수 회원은 여러 과제를 만들 수 있고, 회원은 여러 조 참여 기록을 가질 수 있다.

1-2. 논리적 데이터 모델 — 속성

|속성명               |식별자|필수 여부|근거                      |
|------------------|---|-----|------------------------|
|회원 번호(id)         |예  |필수   |회원 한 명을 구분하기 위해 필요함     |
|이메일(email)        |아니오|필수   |로그인 아이디이며 중복될 수 없음      |
|이름(name)          |아니오|필수   |화면에 회원 이름을 표시함          |
|회원 유형(member_type)|아니오|필수   |교수 또는 학생 중 하나           |
|비밀번호(password)    |아니오|선택   |구글 로그인 회원은 비밀번호가 없을 수 있음|

1-3. 논리적 데이터 모델 — 관계

|상대 엔티티           |관계           |설명                                                   |
|-----------------|-------------|-----------------------------------------------------|
|과제(assignment)   |회원 1 : 과제 N  |교수 회원 한 명은 여러 과제를 만들 수 있다. 과제 하나는 만든 교수 회원 한 명과 연결된다.|
|조 참여(team_member)|회원 1 : 조 참여 N|회원 한 명은 여러 조 참여 기록을 가질 수 있다. 조 참여 하나는 회원 한 명에 속한다.   |

1-4. 물리적 데이터 모델 (PostgreSQL)

테이블 이름: member

|컬럼명        |데이터 타입      |NULL|제약조건  |설명                           |
|-----------|------------|----|------|-----------------------------|
|id         |bigint      |불가  |PK    |회원 번호, 자동 증가                 |
|email      |varchar(255)|불가  |UNIQUE|로그인 이메일, 중복 불가               |
|name       |varchar(255)|불가  |없음    |회원 이름                        |
|member_type|varchar(20) |불가  |CHECK |PROFESSOR 또는 STUDENT         |
|password   |varchar(255)|허용  |없음    |비밀번호 해시 값, 구글 로그인 회원은 NULL 가능|

참고: 회원은 위 두 관계에서 1 쪽이므로 member 테이블에는 외래키(FK)를 두지 않는다. 외래키는 N 쪽 테이블에 둔다.

이 실습에서 꼭 할 것

email 컬럼에 UNIQUE 제약조건을 설정하여 같은 이메일이 중복 등록되지 않게 한다.

1-5. 생각해 볼 질문

질문: 회원 유형을 숫자(교수 0, 학생 1)로 저장하는 방법과 글자(PROFESSOR, STUDENT)로 저장하는 방법 중 하나를 선택하고 이유를 적는다.

답: 글자로 저장하는 방법을 선택했습니다. 숫자보다 값의 의미를 바로 알 수 있어서 이해하기 쉽습니다. 데이터를 확인하거나 오류를 찾을 때도 편리하다고 생각합니다.

1-6. CREATE TABLE (선택)

CREATE TABLE member (
    id          bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    email       varchar(255) NOT NULL UNIQUE,
    name        varchar(255) NOT NULL,
    member_type varchar(20) NOT NULL
                CHECK (member_type IN ('PROFESSOR', 'STUDENT')),
    password    varchar(255)
);
