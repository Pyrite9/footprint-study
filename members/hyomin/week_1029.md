컴포넌트가 무엇이고, 화면을 컴포넌트로 나누면 무엇이 좋은지 씁니다.
ㄴ 리액트에서 화면을 구성하는 독리적인 ui요소(헤더, 사이더 , 메인 등)

화면을 컴포넌트로 나누면 좋은점 
ㄴ 한번 만든 컴포넌트를 여러 화면에서 다시 사용 가능하다.
ㄴ 특정 부분에 문제가생기면 그 부분만 수정하면 된다
ㄴ 여러 개발자가 각각 다른 컴포넌트를 맡아 개발할 수 있다

요약 : 코드를 효율적으로 관리하고 유지보수 쉬워짐


state와 props가 무엇인지, 둘이 어떻게 다른지 씁니다.

state와 props는 리액트에서 데이터를 관리하는 방법이다.

state : 컴포넌트 내부에서 관리하는 데이터, 사용자의 행동에 따라 값이 변경될 수 있다.

props : 부모 컴포넌트가 자식 컴포넌드에게 전달하는 데이터, 자식 컴포넌트에서 전달받은 props를 직접 수정할 수 없다.


state가 바뀌면 화면이 어떻게 다시 그려지는지 씁니다.
ㄴ 리액트에서는 state가 변경되면 해당 state를 사용하는 컴포넌트가 다시 렌더링됨
ㄴ 진행과정 :
1. 사용자가 버튼을 클릭
2. State 변경 함수 setState 또는 setCount 등이 실행
3. 리액트가 State가 변경된 것을 확인
4. 컴포넌트를 다시 실행하여 새로운 화면을 계산
5. 이전 화면과 새로운 화면의 차이를 비교
6. 실제 DOM에서 변경이 필요한 부분을 업데이트

ㄴ 이 과정에서 Virtual DOM이 사용됨
ㄴ Virtual DOM : 실제 브라우저 DOM을 바탕으로 화면의 변경사항을 효율적으로 계산하기 위한 리액트 표현방식

데이터가 한 방향으로 흐른다는 것이 무슨 뜻인지 씁니다.
ㄴ 부모 컴포넌트가 자식 컴포넌트 방향으로 전달하는 것을 의미, 자식은 부모가 전달한 함수를 수정 불가함. 
ㄴ 부모 컴포넌트가 자식 펌포넌트에 props를 전달하면 자식 컴포넌트는 전달받은 데이터를 사용함.

React Router가 무엇이고 왜 필요한지 씁니다.
ㄴ 리액트로 만든 웹사이트에서 페이지 이동과 주소 관리를 할 수 있도록 도와주는 라이브러리
ㄴ 일반적인 웹사이트는 다른 페이지로 이동할 떄 새 html 문서를 불러오는 경우가 많음, 리액트는 하나의 html 페이지를 기반으로 필요한 화면만 변경한다.

React Router를 사용하면 URL에 따라 다른화면을 보여주거나 뒤로가기와 앞으로 가기 등의 기능을 구현할 수 있다.

주소가 바뀔 때 화면이 바뀌는 과정을 순서대로 씁니다.
진행과정 :
1. 사용자가 링크 클릭
2. React Router가 브라우저의 URL 변경
3. 변경된 URL에 맞는 Route 찾음
4. 해당 Route에 설정된 컴포넌트를 화면에 보여줌


TypeScript가 무엇이고 왜 만들어졌는지 씁니다.
ㄴ 자바스크립트에서 발생할 수 있는 타입관련 실수를 줄이기위해 만들어짐

JavaScript에서 타입 때문에 생기는 실수 예시
let a = 10;
let b = "20";

console.log(a + b);     // 결과: 1020
console.log(a + Number(b));   // 결과: 30

첫번째 결과가 1020인 이유는 문자열과 숫자를 더하면 숫자가 문자열로 변환되기 때문
     

JavaScript에서 이런 실수를 줄이는 방법을 씁니다.
1. 옵셔널 체이닝 (?.): 객체나 속성이 존재하지 않을 수 있을때 오류가 발생하지 않도록 하는기능

2. 널 병합 연산자 (??) : 값이 null 또는 underined일때 기본값을 지정하는 기능
